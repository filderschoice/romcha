# Romcha（ロムチャ）計画書（PLAN）

作成日: 2026-09-27
状態: ドラフト（ユーザー判断事項は 2026-09-27 に確定済み。「未確認」の項目は M0 PoC で確定させる）

## 1. 概要

YouTube 公式アプリで動画を視聴しながら、その動画のチャット（ライブチャット／チャットリプレイ）を
フローティングウィンドウでタイムライン表示する Android 向けコメントビューワー。
公式アプリの再生位置を自動取得し、チャットの投稿時刻（動画内オフセット）と同期して表示する。

### 1.1 提示要件（原文の整理）

| ID | 提示要件 |
| --- | --- |
| R-01 | Android アプリである |
| R-02 | YouTube のチャットを追従してタイムライン表示するコメントビューワー |
| R-03 | YouTube 公式アプリと同時に使うため、フローティング表示できる |
| R-04 | 公式アプリの再生時刻を取得し、チャット投稿時刻と自動同期する |
| R-05 | 公式アプリがアクティブウィンドウ／フローティング（PiP）のどちらの状態でも同期できる |
| R-06 | チャット参照のみ。コメント投稿などの機能は持たない |
| R-07 | プレミア公開・アーカイブ動画の両方に対応する |
| R-08 | Google Play では公開せず、GitHub で APK を公開する |
| R-09 | 機能の実現方法が他アプリで実装されている場合は参考にする。参考にする可能性を踏まえてライセンスを設定する（初めから決まっている参考元は無い） |

## 2. 機能要件（肉付け）

### 2.1 動画の特定（F-VID）

ユーザー操作なしの自動特定を基本とする。公式アプリの再生情報（MediaSession）から動画IDが直接取れるかは
未確認（4.2）のため、複数の手掛かりを順に試す自動特定パイプライン（4.3）で特定し、
どうしても特定できない場合に限って共有操作・URL入力で補う。

| ID | 要件 | 優先度 |
| --- | --- | --- |
| F-VID-01 | 公式アプリで再生中の動画を、ユーザー操作なしで自動特定してチャットを開く（4.3） | MUST |
| F-VID-02 | 自動特定の確度が閾値未満の場合は候補を提示し、ユーザーが選べる。誤特定時はワンタップで候補を切り替えられる | MUST |
| F-VID-03 | 公式アプリで別の動画に切り替わったことを検知し、自動で再特定する | MUST |
| F-VID-04 | 自動特定できない場合の代替として、公式アプリの「共有」から URL を受け取る（`ACTION_SEND`） | MUST |
| F-VID-05 | URL 手入力で動画を開ける（`youtu.be` / `watch?v=` / `live/` / `shorts/` 形式を受理） | MUST |
| F-VID-06 | 本アプリが前面にある時にクリップボード内の YouTube URL を検出して提案する | MAY |
| F-VID-07 | チャットが無効・存在しない動画では、その旨を表示する | MUST |

### 2.7 将来対応（F-FUT、v1.0 以降）

| ID | 要件 | 備考 |
| --- | --- | --- |
| F-FUT-01 | Google アカウントでログインし、メンバー限定・年齢制限付き動画のチャットを取得する | 下記の制約を満たす設計を別途行う |

F-FUT-01 の設計上の制約（着手時に詳細化する）:

- ログインは Google の公式ログイン画面（WebView 等）で行い、本アプリはパスワードを入力・保持しない。
- 取得した認証情報（Cookie 等）は Android Keystore で暗号化して端末内にのみ保存し、ログ・外部へ出さない。
- ログアウトで認証情報を完全に削除できる。
- 非公式APIをログイン状態で使うため、アカウント制限のリスクがあることを利用者に明示する。
- 実アカウントを使う検証は人手検証とし、エージェントの自動検証の対象外とする。

## 4. 実現方式

### 4.1 全体構成

```text
┌──────────── YouTube 公式アプリ ────────────┐
│ MediaSession（位置・状態・速度・メタデータ） │
└───────────────────┬─────────────────────────┘
                    │ MediaSessionManager.getActiveSessions
                    ▼   （NotificationListenerService の許可が必要）
┌───────────────── Romcha ──────────────────────────────────┐
│ PlaybackMonitor ──▶ SyncEngine ◀── ChatRepository ──▶ YouTube（InnerTube）
│      │                  │              ▲
│      ▼                  ▼              │
│ VideoResolver      OverlayService（フォアグラウンドサービス + WindowManager）
│ （共有URL/推定）         └─ チャットタイムライン表示
└───────────────────────────────────────────────────────────┘
```

### 4.2 公式アプリの再生位置取得（R-04 / R-05）

- **方式**: `NotificationListenerService` を実装し、ユーザーに「通知へのアクセス」を許可してもらう。
  その上で `MediaSessionManager.getActiveSessions(ComponentName)` から
  パッケージ名 `com.google.android.youtube` の `MediaController` を取得する。
- **取得値**: `PlaybackState.position` / `lastPositionUpdateTime` / `playbackSpeed` / `state`、
  `MediaMetadata` のタイトル・アーティスト（チャンネル名）・長さ。
- **現在位置の推定**:
  `現在位置 = position + (SystemClock.elapsedRealtime() - lastPositionUpdateTime) × playbackSpeed`
  （`STATE_PLAYING` の時のみ加算）。表示更新は 250ms 間隔、状態変化は `MediaController.Callback` で即時反映。
- **PiP・全画面の違い**: MediaSession は表示形態に依存しないため、同一方式で両対応できる見込み。
- **不採用**: AccessibilityService による画面読み取り。権限が過大で、画面構成の変更に弱いため。
- **M0 の実機検証結果（2026-09-27、Pixel 8 Pro / YouTube 21.38.130。当時の `docs/VERIFICATION.md` 1 章。確認済みのため削除済み）**:
  - Premium 有り／無しの両環境で、通常表示・全画面・一時停止・PiP・バックグラウンド再生・広告再生中・ライブ視聴中の
    いずれでも MediaSession が公開され、状態・位置（シークバーと数秒以内）・速度・タイトル・チャンネル名・長さが取れる（Q-01）。
  - `MediaMetadata` ほか全キーに動画IDは含まれない（Q-02）。4.3 の手順1は使えず、手順2以降で特定する。
  - 広告再生中もタイトル等のメタデータは本編の値のままで、位置は広告自体の再生位置（0 付近から進む）、状態・操作も本編と同じ。
    MediaSession の値だけでは広告と本編を区別できない。広告中の同期ずれは既知の制約として README で案内し、検知はしない
    （2026-09-27 決定。K-05）。

### 4.3 動画の特定（F-VID）

自動特定パイプライン。上から順に試し、確定した時点で打ち切る。

| 手順 | 手掛かり | 確度 | 備考 |
| --- | --- | --- | --- |
| 1 | MediaSession から動画IDを直接取得: `MediaMetadata` の全キー（`METADATA_KEY_MEDIA_ID` / `METADATA_KEY_MEDIA_URI` 等）、`MediaDescription` の mediaId / mediaUri、`MediaController.getQueue()` の各項目、extras | 確定 | M0 の実機検証で取れないと確認した（Q-02）。実装は将来の変化に備えて全キーの確認を残す |
| 2 | 端末内キャッシュ: 本アプリが過去に特定した「タイトル＋チャンネル名＋長さ → 動画ID」 | 確定 | 同じ動画を見直す場合に通信なしで確定 |
| 3 | ライブ・プレミア判定: 長さが 0／不明なら配信中とみなし、チャンネル名から当該チャンネルの配信中・プレミア公開中の動画を取得してタイトル照合 | 高 | R-07 のプレミア公開中、通常ライブに有効 |
| 4 | 検索照合: タイトル＋チャンネル名で検索し、タイトル一致・チャンネル名一致・長さ一致（±2秒）で採点 | 採点次第 | 閾値以上で自動確定、未満は候補提示（F-VID-02） |
| 5 | 代替: 共有操作・URL入力（F-VID-04/05） | 確定 | 1〜4 で特定できない場合のみ案内する |

検討して不採用とした方式:

- 通知や MediaSession が持つ `PendingIntent`（`sessionActivity` 等）から URL を読む: 他アプリから中身を読めない仕様のため不可。
- AccessibilityService で公式アプリの画面から読み取る: 画面に動画IDは表示されず、権限が過大なため不採用。
- YouTube アカウントの再生履歴から取得する: ログインが必要。F-FUT-01 着手時に再検討する。

動画の切り替え検知（F-VID-03）: メタデータのタイトル・チャンネル名・長さのいずれかが変化したら、
パイプラインを最初から実行し直す。

### 4.4 チャット取得（R-02 / R-07）

YouTube Data API v3 の `liveChatMessages` はライブ中のチャットのみでリプレイを取得できず、API キーと
クォータも必要なため、主経路には使わない。公開 OSS（chat-downloader・pytchat・yt-dlp 等）と同様に、
YouTube Web クライアントが使う内部 API（InnerTube）を利用する。

| 状態 | 取得方法（概要） | 同期キー |
| --- | --- | --- |
| アーカイブ | `watch` ページ／`next` 応答からリプレイ用 continuation を取得し、`live_chat/get_live_chat_replay` を `playerOffsetMs` 付きで呼ぶ | `videoOffsetTimeMsec` |
| プレミア・ライブ中 | ライブ用 continuation で `live_chat/get_live_chat` をポーリング（応答の推奨間隔に従う） | 受信時刻＋表示遅延 |
| プレミア待機中 | ライブ用と同じ | 受信時刻 |

- 応答 JSON は `kotlinx.serialization` の `JsonElement` で必要箇所のみ辿る（全体を型定義しない）。
- **リスク**: 非公式APIのため予告なく変わる。YouTube 利用規約上の位置付けも公式APIと異なる（5.5）。

### 4.5 同期エンジン（F-SYNC）

- リプレイ: 取得済みメッセージを `videoOffsetTimeMsec` 昇順のバッファに保持し、
  `推定位置 + 手動補正` 以下のものを順次表示へ流す。
- シーク判定: 前回推定位置との差が「経過時間×速度 ± 2秒」を超えたらシークとみなし、
  表示をクリアして新位置から再取得（直前 30 秒分を遡って表示）。
- 先読み: 推定位置の先 60 秒分が常にバッファにある状態を保つ。

### 4.6 フローティングウィンドウ（R-03）

- `SYSTEM_ALERT_WINDOW` 権限＋`WindowManager.addView`（`TYPE_APPLICATION_OVERLAY`）。
- フォアグラウンドサービスで常駐（`foregroundServiceType="specialUse"` を宣言）。
  Play 配布ではないため Play の申告審査は不要だが、OS 側の制約（通知表示・起動条件）には従う。
- タッチ透過モード: `FLAG_NOT_TOUCHABLE` を付与。透過度 0.8 を超えるオーバーレイ越しの
  タッチが遮断されるため、透過モード時は不透明度を 0.8 以下に制限する。
- 通常時は `FLAG_NOT_FOCUSABLE` で公式アプリのキー入力・操作を妨げない。
- UI は Jetpack Compose（`ComposeView` にサービス用の `LifecycleOwner` / `SavedStateRegistryOwner` を設定）。

| 通知へのアクセス（`BIND_NOTIFICATION_LISTENER_SERVICE`） | MediaSession 取得 | 設定画面でユーザーが許可 |
| `FOREGROUND_SERVICE` / `FOREGROUND_SERVICE_SPECIAL_USE` | 常駐 | 自動 |
| `POST_NOTIFICATIONS` | 常駐通知 | 実行時許可 |

通知へのアクセスは本来、通知内容を読める強い権限のため、本アプリは通知本文を読まず MediaSession 取得にのみ
使う旨を権限案内画面と README に明記する。

## 5. ライセンス方針（R-09）

### 5.1 基本姿勢

- 開始時点で決まっている参考元は無い。機能を実現する方法が他アプリで実装されていれば、その都度参考にする。
- 参考元は Android アプリに限らない。Windows 版などのコメントビューワー、チャット取得ライブラリ
  （Python・C#・JavaScript 等）も対象とする。
- 参考にするのは原則として「実現方法」（通信の手順、応答の構造、同期の考え方など）とし、
  本アプリのコードは Kotlin で自分で書く。コードをそのまま流用・移植するのは、ライセンス上問題ないと
  確認できた場合に限る。

### 5.2 参考にするときの判断基準

| 参考元の状態 | 参考にしてよい範囲 | 本アプリのライセンスへの影響 |
| --- | --- | --- |
| 動作・画面を見るだけ（ソースを見ない） | 制約なし | なし |
| ソースを読み、方式（手順・API の呼び方・応答の構造）だけを参考にして自分で書く | 可 | なし（アイデアや手順そのものは著作権の保護対象外） |
| MIT / BSD / Apache-2.0 / Unlicense のコードを流用・移植 | 可 | どのライセンスでも可。著作権表示とライセンス文の同梱が必要（Apache-2.0 は NOTICE も） |
| GPL-3.0 のコードを流用・移植、またはライブラリとして利用 | 本アプリが GPL 互換なら可 | 本アプリも GPL-3.0 以上にする必要がある |
| ライセンス表記の無い公開リポジトリ | 方式の参考まで。コード流用は不可 | なし（流用しない前提） |
| 非公開ソースのフリーソフト（Windows 版コメントビューワーに多い） | 動作・画面の参考まで | なし。利用規約で逆アセンブル・解析が禁止されていることが多いため解析はしない |

注意: 別の言語（C#・Python 等）のコードを Kotlin に書き写す場合も、処理の構成や記述を写していれば
流用（派生物）として扱う。方式だけを参考にしたと言えるように、参考元を見ながら行単位で書き写さない。

### 5.3 参考元の記録

- 参考にした時点で `docs/REFERENCES.md` に 1 件ずつ記録する。
  記録項目: 名称・URL・確認したライセンス・参考にした範囲（動作／方式／コード流用）・参考にした機能要件ID・確認日。
- コードを流用・移植した場合は、そのファイル先頭に元のリポジトリ・コミット・ライセンスを記載し、
  `THIRD_PARTY_NOTICES.md` へライセンス文を追加する。
- 依存ライブラリはアプリ内の OSS ライセンス画面（AboutLibraries）で表示する。

### 5.4 本アプリのライセンス

- **決定（2026-09-27）: MIT**。リポジトリ直下に `LICENSE`（MIT）を置く。
- MIT であることによる制約と運用:
  - GPL のコードは流用・移植・ライブラリ利用のいずれもしない（例: NewPipeExtractor は使わない）。
    GPL の参考元は、5.2 の「方式だけを参考にして自分で書く」範囲に限る。

### 5.5 アプリ名・商標・規約

- **アプリ名（2026-09-27 決定）**: Romcha（ロムチャ）
  - 由来: ROM（Read Only Member＝書き込まずに見るだけの人）＋チャット。コメント投稿機能を持たない
    閲覧専用のチャットビューワーであることを表す。
  - 「浮かぶ（フローティング）」の性格は名前に含まれないため、副題で補う
    （例: 「Romcha — YouTube 公式アプリと同期する、見るだけのフローティングチャットビューワー」）。
  - アプリID: `io.github.filderschoice.romcha`。リポジトリ名も `float-cm-viewer` から `romcha` へ変更する（GitHub 上のリポジトリ名とローカルのディレクトリ名の変更はユーザーが実施）。
  - 名称の衝突調査（Q-08、2026-09-27、Web 検索と GitHub リポジトリ検索）:
    - 「Romcha」「ロムチャ」を名乗るアプリは見当たらない。GitHub には同名のユーザー名が数件あるのみ。
    - 当初の候補「Wisp Chat」は、同名のチャットサービス（wisp.chat）や Wisp 系のチャット・SNS アプリが
      複数あり、検索で埋もれる・関連アプリと誤認されるおそれがあるため不採用とした。
    - 商標データベース（J-PlatPat・USPTO）は未調査。非商用の GitHub 配布のため、必要になった時点で確認する。
- アプリ名・アイコンに YouTube のロゴや名称を使わない（説明文中の「YouTube 対応」表記に留める）。
- 非公式APIの利用は YouTube 利用規約上グレーであり、仕様変更で動かなくなる可能性がある旨を README と
  アプリ内で明示する。

## 6. 配布（R-08）

| 項目 | 方針 |
| --- | --- |
| 配布物 | GitHub Releases に署名済みリリース APK（`romcha-vX.Y.Z.apk`）と SHA-256 を添付 |
| 署名 | リリース用キーストアはリポジトリに含めない（`.gitignore` で除外）。紛失すると上書き更新できないため別途バックアップ |
| バージョン | SemVer。`versionCode` は単調増加 |
| 更新通知 | GitHub Releases API で最新タグを確認し、新版があればダウンロードページを開く（F-APP-02） |
| 更新の互換 | 同一署名での上書きインストールを前提とする。署名変更は破壊的変更として扱う |
| 外部ツール | Obtainium 等の GitHub 追従インストーラから取得できるよう、アセット名を固定する |
| ビルド | 当面はローカルビルド。CI（GitHub Actions）でのビルド・署名は別途検討（CI 定義の変更は人が判断） |
| ロールバック | 旧版 APK を Releases に残す。`versionCode` が下がるためダウングレードはアンインストールが必要（設定は消える） |
