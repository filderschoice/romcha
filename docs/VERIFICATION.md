「結果」欄の記入値:

| 記入値 | 意味 |
| --- | --- |
| `OK` | 確認内容を満たした |
| `NG：<内容>` | 満たさなかった。起きたこと・表示された文言・操作の直前の状態を書く |

アプリを修正して再インストールした場合、その修正に関わる項目は `未実施` に戻して確認し直します。

## 0. 準備

### 0.1 インストール（済みの場合は不要）

```sh
# 端末が複数見える場合（USB と Wi-Fi の二重表示を含む）はシリアルを必ず指定する
adb devices -l
# PowerShell
$env:ANDROID_SERIAL = "39181FDJG008MY"; .\gradlew.bat :app:installDebug
# 確認: lastUpdateTime がインストールした時刻になっていること
adb -s 39181FDJG008MY shell dumpsys package io.github.filderschoice.romcha | findstr "versionName lastUpdateTime"
```

### 0.2 権限の許可（F-APP-01 の確認を兼ねる）

1. Romcha を起動する。「必要な権限」に 3 項目が並び、未許可の最初の項目が強調されていることを確認する。
2. 「他のアプリの上に重ねて表示」の「設定を開く」→ Romcha を許可 → 戻る。
3. 「通知へのアクセス」の「設定を開く」→ Romcha を許可 → 戻る。
   - 許可のスイッチが押せず「制限付き設定」と表示された場合は、設定 → アプリ → Romcha → 右上のメニュー →
     「制限付き設定を許可」を行ってから再度許可する（adb で入れた場合は通常出ないが、APK を手動で入れた場合に出る）。
     出た場合は結果の記録に書く（配布時の README へ案内を追加するため）。
4. 「通知の表示」の「設定を開く」→ 許可する。
5. 3 項目すべてが「許可済み」になることを確認する。

確認コマンド（任意）:

```sh
# 通知へのアクセス: 出力に io.github.filderschoice.romcha/...MediaListenerService が含まれれば許可済み
adb -s 39181FDJG008MY shell settings get secure enabled_notification_listeners
# オーバーレイ: SYSTEM_ALERT_WINDOW: allow なら許可済み
adb -s 39181FDJG008MY shell appops get io.github.filderschoice.romcha SYSTEM_ALERT_WINDOW
```

### 0.3 記録の取り方

- 画面の記録: `adb -s 39181FDJG008MY shell screencap -p /sdcard/shot.png` の後に
  `adb -s 39181FDJG008MY pull /sdcard/shot.png shot-<番号>.png`（手元の端末でスクリーンショットでもよい。
  PowerShell で `exec-out ... >` とリダイレクトすると版によって画像が壊れるため使わない）
- 診断情報: Romcha の「診断情報を表示」の文字列は長押しで選択・コピーできる。メモアプリ等に貼って保存する。
- 動画のタイトル・チャンネル名・URL は、検証に使った動画を後から特定できるように控える。

## 1. BL-021: MediaSession の公開条件と動画IDの取得可否（M0、Q-01 / Q-02）

Romcha の診断情報は、アプリの画面を開いている間だけ更新されます。公式アプリで状態を作ってから Romcha へ
切り替えて表示を確認します（Romcha が前面でも、公式アプリの MediaSession は残ります）。

### 1.1 手順

各状態について、公式アプリで状態を作る → Romcha を開く → 「診断情報を表示」→ 内容をコピーして保存する。

| 番号 | 状態 | 公式アプリでの操作 | 結果 |
| --- | --- | --- | --- |
| A1 | 通常表示で再生中 | アーカイブ動画（長さ 10 分以上）を再生する | 未実施 |
| A2 | 全画面で再生中 | A1 の動画を全画面にする（切り替え後すぐ Romcha を開く） | 未実施 |
| A3 | 一時停止中 | A1 の動画を一時停止する | 未実施 |
| A4 | PiP で再生中 | 再生中にホームへ戻り PiP にする | 未実施 |
| A5 | バックグラウンド再生中 | Premium のみ。画面を離れても再生が続く状態 | 未実施 |
| A6 | 広告の再生中 | Premium 無しのみ。広告が流れている間に開く | 未実施 |
| A7 | ライブ・プレミア視聴中 | 配信中の動画を再生する | 未実施 |

- Premium 有り／無しの両方で行う（どちらか一方しか用意できない場合は、その旨を記録する）。
- 1.1 の「結果」欄には、その状態で 1.2 の観点をすべて満たしたかを書く（NG の場合は満たさなかった観点と値）。

### 1.2 確認

| 観点 | 確認内容 | 結果 |
| --- | --- | --- |
| セッション検出 | 1 行目が「公式アプリの再生を検出していません」ではなく `status = ...` で始まる | 未実施 |
| 状態 | A1・A2・A4・A5 は `PLAYING`、A3 は `PAUSED` | 未実施 |
| 位置 | `position` が公式アプリのシークバーの位置とおおむね一致（数秒以内） | 未実施 |
| 速度 | 公式アプリで再生速度を 1.5 倍にすると `speed = 1.5` になる | 未実施 |
| メタデータ | `title` が動画タイトル、`channel` がチャンネル名、`duration` が動画の長さ（ミリ秒）。A7 では `duration` が 0 か不明 | 未実施 |
| 動画ID（Q-02） | `videoIdHints` が空でないか。空の場合も `---` 以下の全キー一覧を保存する（ID を含むキーが無いかを後で調べる） | 未実施 |
| 広告（A6） | 広告中の `title` / `duration` / `position` が本編と区別できるか（区別できる値があれば控える） | 未実施 |

## 2. BL-023: アーカイブのリプレイ同期（N-02）

### 2.1 手順

1. Romcha で「フローティング表示を開始」を押す。常駐通知「Romcha を表示中」が出てウィンドウが表示される。
2. チャットリプレイのあるアーカイブ（ライブ配信・プレミア公開の終了後の動画）を公式アプリで再生する。
3. 以下を順に行う。

| 番号 | 操作 | 確認 | 結果 |
| --- | --- | --- | --- |
| B1 | 再生を始める | 数秒以内にウィンドウのタイトルが動画名になり、状態が「同期中」、チャットが流れ始める | 未実施 |
| B2 | 公式アプリのチャットリプレイ（縦画面の「チャットのリプレイを表示」）と見比べる | 同じコメントの表示時刻のずれが ±1 秒以内 | 未実施 |
| B3 | 一時停止する | 状態が「一時停止」になり、チャットの追加が止まる | 未実施 |
| B4 | 10 分先へシークする | 2 秒以内に表示が作り直され、シーク先の直前 30 秒ぶんから流れる | 未実施 |
| B5 | 10 秒戻し・10 秒送りを数回行う | そのたびに表示が作り直され、移動先の位置に合ったチャットが流れる（重複・欠落が目立たない） | 未実施 |
| B6 | 再生速度を 2 倍・0.5 倍にする | チャットの流れる速さが追従する | 未実施 |
| B7 | PiP にする | PiP でも同期が続く | 未実施 |
| B8 | 全画面にする | 全画面でも同期が続き、ウィンドウが公式アプリの操作を妨げない（ウィンドウ外はタップできる） | 未実施 |
| B9 | 別のアーカイブ動画へ切り替える | 数秒以内に新しい動画を特定し直し、チャットが切り替わる（F-VID-03） | 未実施 |
| B10 | 画面を消して 1 分後に点ける | 消灯中は取得が止まり、点灯後に同期が再開する（N-03） | 未実施 |

### 2.2 ウィンドウと特定の確認（あわせて行う）

| 番号 | 操作 | 確認 | 結果 |
| --- | --- | --- | --- |
| C1 | ヘッダーをドラッグ／右下のハンドルをドラッグ | 移動・サイズ変更ができ、画面外へはみ出さない | 未実施 |
| C2 | 設定ボタン → 背景のスライダー | 背景の透過度が変わる。一度閉じて開き直しても保持される | 未実施 |
| C3 | 一覧を上へスクロールして止める | 自動スクロールが止まり「最新へ」ボタンが出る。押すと最下部へ戻り追従を再開する | 未実施 |
| C4 | スーパーチャットのある場面 | 金額と色帯で強調表示される | 未実施 |
| C5 | 常駐通知の「非表示」「表示」「終了」 | それぞれウィンドウの非表示・再表示・終了ができる | 未実施 |
| C6 | 自動特定できなかった場合 | 候補が表示され、選ぶとその動画のチャットになる。同じ動画を開き直すと通信なしで確定する | 未実施 |

| C8 | Romcha の「URL で開く」に動画 URL を入力 | その動画のチャットが表示される（F-VID-05） | 未実施 |
| C9 | チャットの無い動画（通常の投稿動画） | 「この動画ではチャットを利用できません」等の説明が出る（F-VID-07） | 未実施 |

## 3. BL-024: ライブ・プレミアの追従と終了時の切り替え

配信の時間帯に合わせて行います。プレミア公開は開始前の待機中から確認できると理想です。

| 番号 | 操作 | 確認 | 結果 |
| --- | --- | --- | --- |
| D1 | 配信中のライブを公式アプリで再生 | 状態が「ライブ」になり、最新のチャットが数秒おきに追加される | 未実施 |
| D2 | 公式アプリのチャット欄と見比べる | 取りこぼしが目立たない。映像より先にチャットが流れる場合は D3 | 未実施 |
| D3 | 設定ボタン → 「遅延」スライダーを 5〜10 秒にする | その秒数だけ遅れて表示される。閉じて開き直しても保持される（F-SYNC-08） | 未実施 |
| D4 | 公式アプリで一時停止する | 状態が「一時停止」になり取得が止まる。再開すると追従を再開する | 未実施 |
| D5 | プレミア公開の待機中（開始前）に開く | 待機中のチャットが表示される（F-CHAT-05） | 未実施 |
| D6 | 配信（またはプレミア）の終了まで開いたままにする | 「配信は終了しました。チャットのリプレイの準備を待っています（n 回目）」が出て、準備でき次第リプレイの同期表示へ切り替わる（最大約 18 分待つ）（F-CHAT-06） | 未実施 |

## 4. BL-022: 実際の応答での解析

アプリの取得処理は、既知の応答構造に基づく合成データでしか試験していません。2・3 章でチャットが表示されれば
解析は実際の応答でも動いています。以下を確認・記録してください。

| 番号 | 確認 | 結果 |
| --- | --- | --- |
| E1 | 2・3 章で「チャットの解析に失敗しました（YouTube の仕様変更の可能性があります）」が一度も出ない | 未実施 |
| E2 | 「YouTube からエラーが返されました（HTTP ...）」が出た場合、その番号と操作を記録する | 未実施 |
| E3 | メンバー加入・ギフト・スーパーステッカー・カスタム絵文字（`:_名前:` の代替テキスト）が表示される場面があれば、表示が崩れていないか | 未実施 |
| E4 | ライブ配信中の動画で、長さ不明から自動特定できたか（できなければ候補表示・共有で代替） | 未実施 |

テスト用データ（`core/chat/src/test/resources/fixtures/`）を実際の応答から作り直す作業は、YouTube への実通信を伴うため、
結果の記録を受けてから、エージェントが実施してよいか確認のうえで別途行います（個人に関わる情報は取り除きます）。

## 6. 不具合時に取得すると調査が速い情報

アプリはチャットの内容や個人に関わる情報をログへ出しません（N-07）。落ちた場合は次で原因を取れます。

```sh
# 直前のクラッシュ（アプリが落ちた場合）
adb -s 39181FDJG008MY logcat -d -b crash | findstr /i romcha
# オーバーレイ・通知アクセスの状態
adb -s 39181FDJG008MY shell dumpsys activity services io.github.filderschoice.romcha | findstr /i "ServiceRecord isForeground"
```
