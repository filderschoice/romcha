## 0. 準備

### 0.1 インストール（済みの場合は不要）

```sh
# 端末が複数見える場合（USB と Wi-Fi の二重表示を含む）はシリアルを必ず指定する
adb devices -l
# PowerShell
$env:ANDROID_SERIAL = "<シリアル>"; .\gradlew.bat :app:installDebug
# 確認: versionName が 1.0.1、lastUpdateTime がインストールした時刻になっていること
adb -s <シリアル> shell dumpsys package io.github.filderschoice.romcha | findstr "versionName lastUpdateTime"
```

2 章のように署名済み APK を入れる時は、デバッグ版とは署名が違うため上書きできません。先に
`adb -s <シリアル> uninstall io.github.filderschoice.romcha` で消してください（権限の許可も消えるので 0.2 をやり直す）。

### 0.2 権限の許可（許可済みの場合は不要）

1. Romcha を起動する。「必要な権限」に 3 項目が並び、未許可の最初の項目が強調されていることを確認する。
2. 「他のアプリの上に重ねて表示」の「設定を開く」→ Romcha を許可 → 戻る。
3. 「通知へのアクセス」の「設定を開く」→ Romcha を許可 → 戻る。
   - 許可のスイッチが押せず「制限付き設定」と表示された場合は、設定 → アプリ → Romcha → 右上のメニュー →
     「制限付き設定を許可」を行ってから再度許可する（adb で入れた場合は通常出ないが、APK を手動で入れた場合に出る）。
     出た場合は結果の記録に書く（配布時の README へ案内を追加するため）。
4. 「通知の表示」の「設定を開く」→ 許可する。
5. 3 項目すべてが「許可済み」になることを確認する。

確認コマンド（任意）:

```sh
# 通知へのアクセス: 出力に io.github.filderschoice.romcha/...MediaListenerService が含まれれば許可済み
adb -s <シリアル> shell settings get secure enabled_notification_listeners
# オーバーレイ: SYSTEM_ALERT_WINDOW: allow なら許可済み
adb -s <シリアル> shell appops get io.github.filderschoice.romcha SYSTEM_ALERT_WINDOW
```

### 0.3 記録の取り方

- 画面の記録: `adb -s <シリアル> shell screencap -p /sdcard/shot.png` の後に
  `adb -s <シリアル> pull /sdcard/shot.png shot-<番号>.png`（手元の端末でスクリーンショットでもよい。
  PowerShell で `exec-out ... >` とリダイレクトすると版によって画像が壊れるため使わない）
- 診断情報: Romcha の三点メニュー →「診断情報」（公式アプリの再生情報）の文字列は長押しで選択・コピーできる。
  メモアプリ等に貼って保存する。表示される `title` / `channel` / `duration` が、動画の特定に使う 3 つの値（識別キー）。
- 動画のタイトル・チャンネル名・URL は、検証に使った動画を後から特定できるように控える。
- 配信者名・チャット本文など第三者の情報が写った画像は、共有の前にその部分を隠す。

## 1. BL-073: 「キャッシュを消す」の誤特定からの回復

表示・Toast・消した後のチャット再表示（C1〜C3）は確認済みです。残るのは、誤った動画のチャットが出ている状態からの回復だけです。
同名のライブ配信では誤特定が再現しなかったため（BL-071）、公式アプリで動画を見ていて別の動画のチャットが偶発的に出た時に行います。

| 番号 | 操作 | 確認 | 結果 |
| --- | --- | --- | --- |
| C5 | 別の動画のチャットが出ている状態で、診断情報の `title` / `channel` / `duration` を控え、「キャッシュを消す」を押す | 正しい動画（公式アプリで見ている動画）のチャットへ切り替わる | OK |

## 2. BL-058: 新版の通知（「更新を確認」）

前提: リポジトリは 2026-10-04 に公開済みです。非公開の間は「公開されている版はまだありません。」になっていました
（2026-09-28 確認済み）。署名済み APK は GitHub Releases の v1.0.0 と v1.0.1 から取得します。

| 番号 | 操作 | 確認 | 結果 |
| --- | --- | --- | --- |
| P3a | v1.0.1 をアンインストールし、Releases の v1.0.0 の APK を入れる。「更新を確認」を押す | 「新しい版 1.0.1 が公開されています。」と「ダウンロードページを開く」が出る | OK |
| P3b | 「ダウンロードページを開く」を押す | ブラウザーで最新リリースのページが開く（アプリ内で自動インストールはされない） | OK |

最後に、使い続ける版を入れ直してください（デバッグ版が必要なら `.\gradlew.bat :app:installDebug`。署名が違うため先にアンインストール）。

## 3. BL-082: UI 改善の表示と操作

前提: UI 改善（BL-077〜BL-081）を含むデバッグ版を 0.1 の手順で入れ、権限をすべて許可しておきます。
U1〜U6 は表示設定のテーマを「ダーク」と「ライト」の両方で確かめ、帯の上の文字が読めることも見ます。

| 番号 | 操作 | 確認 | 結果 |
| --- | --- | --- | --- |
| U1 | フローティング表示を開始し、公式アプリでアーカイブ動画を再生し始める | 「再生中の動画を特定しています…」「チャットを読み込んでいます…」が灰色の帯で出る（赤ではない）（BL-077） | OK |
| U2 | 機内モードにしてから別のアーカイブ動画を再生する | 「通信できません。接続を確認してください」が赤帯で出る。確認後に機内モードを戻す（BL-077） | OK |
| U3 | アーカイブ動画の冒頭（チャットが流れる前）で一覧を見る | 一覧の中央に「まだ表示するチャットはありません」が出て、チャットが届くと消える（BL-078） | OK |
| U4 | アプリの表示設定で「スーパーチャットのみ」をオンにし、スーパーチャットの無い区間を再生する | 一覧の中央に「絞り込みの条件に合うチャットはありません」が出る。確認後にオフへ戻す（BL-078） | OK |
| U5 | 表示設定の各スイッチ・テーマの行で、スイッチやラジオボタンではなく文字の部分を押す | 押した行の設定が切り替わる。TalkBack をオンにすると、行が 1 つのスイッチ・ラジオボタンとして読まれる（BL-079） | OK |

## 5. 不具合時に取得すると調査が速い情報

アプリはチャットの内容や個人に関わる情報をログへ出しません（N-07）。落ちた場合は次で原因を取れます。

```sh
# 直前のクラッシュ（アプリが落ちた場合）
adb -s <シリアル> logcat -d -b crash | findstr /i romcha
# オーバーレイ・通知アクセスの状態
adb -s <シリアル> shell dumpsys activity services io.github.filderschoice.romcha | findstr /i "ServiceRecord isForeground"
```
