# Copilot / Claude Code 汎用フレームワーク

複数プロジェクトで再利用できる、AIコーディングエージェント（GitHub Copilot、Claude Code など）
応答生成の汎用フレームワークです。プロジェクト固有の運用ルール（共通規約の `.github/copilot-instructions.md`
とエージェント固有差分の `CLAUDE.md`）のベースとなる骨組みを提供します。

本書は導入・移行の判断時に読む文書です。日常のセッションで常時読み込む必要はありません。

## 文書の役割分担

| 文書 | 役割 | 正本とする範囲 |
| --- | --- | --- |
| `rules/guardrails-unified.v1.md` | セキュリティ・ガバナンス統制（常時読み込み） | セキュリティ統制、禁止カテゴリ、プロンプト設計統制、例外・変更管理、自律ループ統制 |
| `rules/guardrails-app.v1.md` | 生成AIアプリ運用統制（必要時に読む） | データ分類・プライバシー、評価ゲート、監視・インシデント対応、コンプライアンス |
| `docs/guidelines/RULE.md`（本書） | 汎用フレームワーク | 基本原則、実装モード別の出力要件、要件トレーサビリティ、Definition of Done |
| `CONTRIBUTING.md` | 人間向け開発プロセス | 規定ブランチ、ブランチ・コミット規約、レビュー要件、エージェント指示ファイルの構成規約 |
| `.github/copilot-instructions.md` | 全エージェント共通の実行ルール | セキュリティ要件、開発プロセス要件、品質・信頼性要件、ドキュメント管理要件、出力要件、Copilot 固有差分 |
| `CLAUDE.md` | Claude Code 固有の差分と追加規約 | 品質ゲートの具体コマンド、記録ファイルの権限設定、自律ループ実行モードの適用条件 |
| `.claude/skills/` | Claude Code のオンデマンド手順 | 自律ループ実行モードの実行手順、ドキュメント整合性レビュー手順 |

## 適用対象

- AIコーディングエージェントによる実装提案、コード生成、差分提案
- 初回実装・追加実装の両方
- 複数プロジェクトで共有可能な汎用指針

## 基本原則

- MUST: 実装に直結する粒度で回答する
- MUST: 未確認事項は「未確認」と明示する
- MUST: 実現困難な要求は、理由・代替案・影響範囲を示す
- SHOULD: 暗黙の仕様変更を避け、既存仕様の維持有無を明記する
- SHOULD: 破壊的変更がある場合は段階的移行案を示す

## 実装モード別ルール

### 初回実装

- プロジェクト構成
- 主要ファイルの完全コード
- セットアップ・ビルド・実行・テスト手順
- 配布・更新・ロールバック方針

### 追加実装

- 変更対象ファイル一覧
- 各ファイルの差分
- 追加・変更テスト
- 互換性影響と移行手順
- 既存機能へのリグレッションリスク
- スキーマ変更時のマイグレーション方針

### 仕様変更の扱い

- 追加実装時に明示されていない要件は既存仕様を維持する（暗黙の仕様変更を禁止）
- 破壊的変更がある場合は段階的移行案を示す

### 自律ループ実行モード

人の応答を待たずに複数イテレーションを連続実行するモードです。採用する場合は、プロジェクト側で以下を
すべて定義してください（未定義のまま運用しないでください）。統制要件は
`rules/guardrails-unified.v1.md` セクション12を参照します。

- MUST: 適用条件（ユーザーの明示指示、作業ブランチ上での実行）
- MUST: 許可されるgit操作の範囲と、禁止される操作（`push`・規定ブランチへのコミット等）
- MUST: 停止条件（禁止操作への到達、品質ゲートの連続失敗、実行可能タスクの枯渇、完了）
- MUST: 人への確認が必要な事項の非同期化手順（確認質問の代替となる記録方法）
- MUST: 自動実行可能な品質ゲートのコマンドと、その合否判定基準
- MUST: ループの完了条件と、自動検証できない項目の除外方法
- MUST: 秘密情報の取り扱い（本番資格情報を用いる検証を自動実行しないこと）
- SHOULD: 対話前提の出力要件を、ファイル成果物・記録ファイルへ読み替える対応表

## 品質・セキュリティ・ドキュメント管理

具体的な要件は、プロジェクト側の共通規約（`.github/copilot-instructions.md`）の以下セクションで定義します。

- 「セキュリティ要件」: 秘密情報・入力検証・方針上書き対策
- 「品質・信頼性要件」: 品質ゲート・データ保護・耐障害性
- 「ドキュメント管理要件」: 記録ファイルの更新規約と書き分け

記録ファイルの記述仕様は `docs/records/spec/FORMAT.md` を唯一の参照元とします。

## 要件トレーサビリティ

- MUST: 要件ごとに「対応済み/未対応/対象外」を明示する
- MUST: 未対応/対象外には理由と暫定対応を付記する
- MUST: 追加実装時は「今回変更する要件」を明示し、未記載要件は既存維持として扱う

## 推奨出力フォーマット

実装提案は以下の順で構成することを推奨します。

実装方針 → 技術選定方針 → 対応範囲宣言 → 変更対象一覧 → 実装コード（初回は全文、追加は差分）
→ セットアップ・ビルド・実行手順 → テスト項目 → 品質ゲート実行結果 → リリース・運用手順
→ 要件対応表 → 既知課題・リグレッションリスク・次ステップ → 手動確認チェックリスト

## Definition of Done（完了条件）

- 実装、実行手順、テスト観点、既知課題がそろっている
- 要件対応表に抜け漏れがない
- 主要ユースケースの成功時・失敗時の挙動を説明できる
- 品質ゲート結果（成功/失敗と根拠）を提示できる

自律ループ実行モードでは、上記に加えて以下も満たす必要があります。

- 未完了タスクが「人手検証待ち」「要確認」のみになっている
- 各イテレーションの実施記録が残っている
- 自動検証できなかった範囲が明示されている

## 運用メモ

- 本書は汎用フレームワークです。プロジェクト固有の制約・運用は、共通規約
  （`.github/copilot-instructions.md`）とエージェント固有差分（`CLAUDE.md`）で補完してください。
- ルール更新時は差分理由を記録し、必要に応じて `CHANGELOG.md` 更新を提案してください。
